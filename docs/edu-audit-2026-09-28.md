## Findings, in suggested repair order

### 1. Revoked sessions retain an open chat subscription — confirmed API probe

`app/hub/routes.py`: `chat_socket`, `logout`, and `add_message`.

Open a student WebSocket, log out that same session through the API, then
post an instructor message. HTTP `/me` returns 401 but the existing socket
still receives the new message. Authentication and membership are checked
only at connection time. Close sockets for revoked sessions and revalidate
access before delivery, including expiration and membership changes. Add
regression coverage for an open socket across logout/revocation.

### 2. Cohort switching retains previous content — confirmed browser reproduction

`frontend/src/main.js`: `selectCohort`, `loadChannels`, `loadQuestions`.

As administrator, open Demo cohort 2026, then select Audit empty cohort.
The channel list clears, but old messages remain visible with an enabled
composer. The old answer heading and question selection also remain. Reset
channel/question state, rendered content, and form availability on cohort
changes; protect asynchronous loads from committing stale responses.
The backend rejects mismatched cohort/channel IDs; this observation does
not demonstrate bypass of backend cohort isolation.

### 3. Intentional logout produces a connection error — confirmed browser reproduction

`frontend/src/main.js`: logout handler and `socket.onclose`.

After successful logout, the login screen can show "Chat connection closed.
Reload to reconnect." because the closing socket remains the current socket.
Detach/invalidate it before closing and reset session-scoped UI state.

### 4. Role and empty/archive controls do not match available actions — mixed evidence

The instructor role selector visibly offers Instructor, although the API
requires administrator access to assign that role. Hide unavailable choices.
Source inspection also shows no disabling of write forms for archived cohorts
and no coherent no-cohort state. Archived writes are rejected by the backend;
the archived workflow was not exercised in this audit.

### 5. Form accessibility and feedback need improvement — browser/source inspection

Several form controls have placeholders but no persistent labels; their
accessibility-tree names are empty. The temporary-password input uses the
text type. The page declares Korean while most UI copy is English. Add
labels, mask passwords, align the declared language with the chosen copy,
and translate structured validation errors into useful field feedback.
Remove database/SFU implementation details from ordinary student-facing copy.

## Pre-deployment hardening (branch `edu/discord-piazza-ui`)

- **Connection cap.** `prototype_run.py` capped uvicorn at 60 concurrent
  connections, and every open chat WebSocket counts toward it; past the cap
  every request gets 503. Raised to 1000. The live `run.py` service on `main`
  is unchanged.
- **Database pool.** `app/hub/db.py` now borrows from a `psycopg_pool`
  pool (default 10 connections, `BAMBOOCHAT_HUB_DB_POOL_SIZE`) instead of
  opening a connection per query. Connections are checked before reuse, so a
  PostgreSQL restart costs no failed request. The pool closes on shutdown.
- **Login throttling.** `/hub/api/login` allows 12 attempts per client IP and
  username per 5 minutes (HTTP 429 after that), matching the legacy app.
  Unknown usernames now verify against a dummy hash, so response time does not
  reveal which usernames exist. Behind a reverse proxy the client IP will be
  the proxy's until forwarded headers are trusted.
- **Uploads.** File bytes are written in a worker thread so a 10 MB upload
  no longer pauses chat delivery.
