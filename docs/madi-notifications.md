# 내 알림과 질문 팔로우

채팅과 Q&A의 공통 메뉴에 **알림**이 있다. 안 읽은 알림 수는 메뉴에 표시되고, 모바일에서 메뉴가 닫혀 있으면 메뉴 버튼에도 점과 접근성 안내가 표시된다.

## 어떤 알림을 받는가

- **질문의 새 답변:** 질문을 작성하거나 답변하면 기본으로 그 질문을 팔로우한다. 다른 사람이 이후 답변하면 알림을 받는다. 질문 상세의 **질문 팔로우 / 팔로우 중 · 해제**로 직접 변경할 수 있다. 한 번 해제한 설정은 다시 답변해도 유지한다.
- **채팅 멘션:** 새 공개 채널 메시지 또는 본인이 참여한 DM에서 `@아이디`로 불리면 알림을 받는다. 본인이 쓴 글은 알림을 만들지 않는다. 한 메시지에서 같은 사람을 여러 번 불러도 한 건이다.
- 아이디를 부분 일치로 찾지 않는다. `@student_long`은 `student`를 부르지 않는다. 이메일, URL, 인라인 코드와 코드 블록 안의 예시는 멘션 알림에서 제외한다. 현재 로그인과 같은 아이디 정규화 규칙을 적용한다.
- 알림은 새 메시지·답변 작성 시 생성한다. 편집·반응·해결 상태 변경은 별도의 알림을 만들지 않는다. 질문의 답변 알림과 채팅 멘션이 이번 기능의 범위다.

## 알림함

전체/안 읽은 알림 필터, 이전 알림 더 보기, 건별 읽음/안 읽음 변경, **모두 읽음**을 제공한다. 알림을 일반 클릭으로 열면 해당 질문 또는 멘션 메시지로 이동한 뒤 읽음으로 표시한다. 오래된 메시지와 DM도 해당 대화와 메시지 위치로 이동하고 새로고침 시 위치를 복원한다. 이전 메시지 문맥에는 **최신 대화로 돌아가기** 버튼이 있다.

알림 읽음과 채널 메시지 읽음은 독립적이다. 모두 읽음은 알림함 상태만 바꾼다. 적용 중 새로 도착한 알림을 읽어 버리지 않도록 현재 확인한 최대 알림 ID까지만 처리한다.

같은 반의 WebSocket 활동과 다른 기기의 알림 읽음 변경 시 배지를 갱신한다. 다른 반을 보고 있어도 탭/창으로 돌아오거나 화면이 보이는 동안 30초 간격으로 전체 반의 알림 수를 조회한다. 알림함을 읽는 도중 알림 수가 바뀌면 새 목록을 확인할 수 있는 안내를 표시한다. 네트워크 장애에는 알림함 안에서 재시도할 수 있다. 브라우저/OS 푸시, 이메일, 소리 알림은 포함하지 않는다.

## 접근 권한과 저장

- 알림은 수신 계정에만 속하며 관리자도 다른 사람의 알림함을 조회하거나 읽음 처리할 수 없다.
- 생성과 조회 모두 수강반 접근 권한을 검사한다. DM은 관리자라도 대화 참여자여야 한다. 비활성 계정과 해당 반에 접근할 수 없는 계정에는 새 알림을 만들지 않는다.
- 질문·답변·메시지가 삭제되거나 반/DM 접근 권한이 없어지면 해당 알림은 목록, 읽지 않은 수, 읽음 처리 대상에서 제외한다. 본문/제목의 별도 영구 스냅샷을 저장하지 않는다.
- 원본 게시물과 알림은 한 트랜잭션에 저장한다. 로그아웃/계정 전환 시 화면의 이전 계정 알림 목록과 갱신 타이머를 정리한다. 첫 로그인 비밀번호 변경 단계에서는 알림 API와 구독을 사용할 수 없다.
- 스키마 `0011_notifications.sql`을 Madi 시작 시 적용한다. 기존의 삭제되지 않은 질문 작성자와 답변 참여자는 팔로우 상태로 이전하지만, 과거 활동 알림은 생성하지 않는다.

## API와 검증

- `GET /hub/api/notifications?unread_only=true&before=ID`: 30건 페이지, 전체/미읽음 수, 다음 커서.
- `GET /hub/api/notifications/unread`: 현재 접근 가능한 미읽음 알림 수.
- `POST /hub/api/notifications/{id}/read`, 본문 `{"read": true}` 또는 `false`.
- `POST /hub/api/notifications/read-all`, 본문 `{"through_id": ID}`.
- `GET /hub/api/cohorts/{cid}/questions/{qid}/follow`, `PUT` 본문 `{"following": true}` 또는 `false`.

백엔드는 폐기 가능한 `MADI_TEST_DATABASE_URL`에서 `python -m pytest tests/test_hub_notifications.py`로 검사한다. 이 테스트는 해당 DB의 `hub_*` 테이블을 초기화하므로 실제 DB를 지정하면 안 된다. 브라우저 검사는 빌드 후 `node scripts/test_notifications_browser.mjs`이며, 기존 브라우저 스크립트와 같은 Playwright/Chrome 환경 변수를 사용한다. 자체 모의 API 서버로 실행해 DB에 접근하지 않는다.
