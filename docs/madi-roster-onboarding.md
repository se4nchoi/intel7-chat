# 수강반 명단 가져오기와 첫 로그인

관리자의 **학원 관리 → 명단으로 계정 가져오기**에서 사용할 수 있다. 화면 공유 및 수업용 8000 서버와 독립적인 Madi 학원 기능이다.

## 사용 방법

1. 배정할 진행 중인 수강반을 선택한다. 수강반이 없다면 위의 새 수강반 폼에서 먼저 만든다.
2. UTF-8 CSV 파일을 선택하거나 Excel/스프레드시트에서 제목 행까지 복사해 붙여 넣는다. 최대 100명, 파일 최대 100KB다.
3. **가져올 내용 미리 확인**으로 계정·역할·신규/기존 처리와 행별 오류를 검토한다. 오류가 있으면 원본을 수정하고 다시 확인한다.
4. **확인한 명단 적용**으로 일괄 생성·배정한다. 입력 또는 수강반을 바꾸면 기존 미리보기는 무효가 된다.
5. 신규 계정의 로그인 정보 CSV를 내려받아 각 사용자에게 전달한다. 임시 비밀번호는 결과 화면을 닫으면 사라지며 다시 조회할 수 없다. 전달하지 못했다면 계정 관리에서 비밀번호를 재설정한다.

```csv
username,display_name,role
stu01,김학생,student
stu02,이학생,student
inst01,박강사,instructor
```

`username`, `display_name` 제목은 필수다. 열 순서를 바꿀 수 있고, `role` 열을 생략하거나 비워 두면 `student`로 처리한다. `학생`/`수강생`, `강사`도 역할 값으로 사용할 수 있다. 쉼표가 있는 이름은 `"김, 학생"`처럼 CSV 인용 규칙을 따른다. 비밀번호 열은 받지 않는다.

미리보기 요약의 신규·배정·이미 배정 인원에는 **오류가 없는 행만** 포함된다. 오류가 한 행이라도 있으면 전체 명단 적용이 차단된다. **오류 행만 보기**로 수정할 행을 모아 확인할 수 있다. 행 번호는 제목 행과 빈 행을 제외한 데이터 순서이며, 따옴표 안의 줄바꿈은 같은 데이터 행으로 센다.

## 처리 규칙

- **신규 계정:** 계정마다 임의 임시 비밀번호를 생성하고 선택한 반에 배정한다. 관리자는 학생·강사 역할을 배정할 수 있지만, 전역 관리자 계정은 이 흐름으로 만들 수 없다.
- **기존 활성 계정:** 기존 이름과 비밀번호를 유지하고 선택한 반에만 추가한다. 같은 역할로 이미 배정되어 있으면 건너뛴다. 기존 소속은 유지된다.
- **기존 역할이 다른 계정:** 행 오류로 표시한다. 역할 변경은 별도의 수강반 관리에서 진행한다.
- **비활성 계정·관리자 계정·중복 아이디·잘못된 행:** 가져오기를 차단한다. 아이디 중복은 기존 로그인과 같은 Unicode 정규화 및 대소문자 규칙을 따른다.
- **일괄 적용:** 한 트랜잭션으로 처리한다. 실패하면 신규 계정과 배정 모두 롤백한다. 미리보기 이후 계정/수강반/소속이 변경되거나 동일한 배치를 동시에 적용하면 재확인을 요구한다.
- **결과 보관:** 비밀번호 원문은 DB·로그·브라우저 저장소에 보관하지 않는다. 결과가 열린 동안 메모리와 화면에만 존재하며 관리 창을 닫거나 지우기 버튼을 누르면 제거한다. 내려받은 CSV에는 로그인 정보가 들어 있다.
- **CSV 호환성:** Excel이 수식으로 해석할 수 있는 값에는 내려받은 CSV에서 작은따옴표를 덧붙인다. 예를 들어 `-`로 시작하는 아이디는 화면의 원문을 기준으로 전달한다. 화면에서 복사하는 로그인 문자열은 그대로 유지된다. 임시 비밀번호는 문자로 시작하도록 발급한다.

## 계정을 하나씩 만드는 경우

**학원 관리 → 새 계정**에서 만든 계정도 명단 가져오기와 같은 첫 로그인 절차를 거칩니다. 관리자가 정한 임시 비밀번호로 로그인한 뒤 본인 비밀번호로 변경해야 수업에 참여할 수 있습니다. 계정 목록의 **첫 로그인 대기** 표시는 아직 이 절차를 마치지 않은 계정에 나타나며, 비밀번호 변경 후 목록을 다시 불러오면 사라집니다.

이미 사용 중인 계정과 `madi_run.py --create-admin`으로 만든 최초 관리자는 이 변경의 대상이 아닙니다. 관리자의 비밀번호 재설정은 기존 정책대로 처리하며, 첫 로그인이 아직 끝나지 않은 계정은 재설정 후에도 변경 의무가 유지됩니다.

## 첫 로그인

새 계정은 임시 비밀번호로 로그인한 뒤 전용 비밀번호 변경 화면으로 이동한다. 새 비밀번호와 확인 값을 입력해야 반에 들어갈 수 있다. 임시 비밀번호와 같은 값은 허용하지 않는다. 이 단계는 새로고침 후에도 유지되고, 서버에서도 반 API와 WebSocket 접근을 막는다.

비밀번호를 변경하면 본인 세션을 유지하면서 다른 세션을 종료한다. 아직 첫 로그인을 마치지 않은 계정의 비밀번호를 관리자가 재발급해도 변경 의무는 유지된다. 기존 계정에는 이 변경 의무를 소급 적용하지 않는다. 로컬 테스트 계정 `stu`/`inst`/`admin`의 로그인 흐름은 유지된다.

## 개발·검증

스키마 `0010_account_onboarding.sql`은 `must_change_password`를 기본 `FALSE`로 추가한다. Madi 시작 시 기존 마이그레이션 절차로 적용된다.

- 관리자 API: `POST /hub/api/accounts/import/preview`, `POST /hub/api/accounts/import`. 본문은 `cohort_id`, `rows`이고 적용에는 미리보기 응답의 `revision`도 필요하다. 행은 `username`, `display_name`, `role`이다.
- 미리보기 응답의 `counts`는 오류 없는 행의 작업별 인원이다. `total_rows`는 전체 데이터 행 수, `invalid_rows`는 오류가 있는 행 수다. 적용은 `valid: true`인 미리보기와 최신 `revision`이 있어야 가능하다.
- 프런트엔드 파서/내보내기: `frontend/src/roster.js`, `npm --prefix frontend test`.
- 백엔드 회귀: 별도 폐기 가능한 `MADI_TEST_DATABASE_URL`을 설정한 뒤 `python -m pytest tests/test_hub_onboarding.py`. 테스트는 해당 DB의 `hub_*` 테이블을 초기화하므로 실제 개발·운영 DB를 지정하면 안 된다.
- 브라우저 회귀: 빌드 후 `node scripts/test_onboarding_browser.mjs`. Playwright/Chrome이 필요하고, 기존 Academy 브라우저 검사와 같은 `PLAYWRIGHT_MODULE_PATH`, `MADI_BROWSER_CHANNEL`, `MADI_TEST_PYTHON` 설정을 사용한다. 자체 임시 서버와 모의 API를 사용하여 DB에 접근하지 않는다.

로컬 검증에서는 별도 `madi_ui_audit` DB에 CSV를 실제 적용해 신규 학생·강사, 기존 구성원 보존, 다운로드, 모바일 미리보기, 첫 로그인 변경·재진입을 확인했다. 실제 학원 명단은 가져오지 않았다. 모바일은 Chrome 화면 크기 에뮬레이션으로 확인했으며 실제 휴대폰의 키보드·파일 선택기는 별도 확인이 필요하다.

2026-10-19 검증: 백엔드 전체 400 passed / 1 skipped, 최종 비밀번호 발급 변경 후 온보딩 8개 재통과, 프런트엔드 27개 통과, Vite 빌드 성공. 자체 모의 API의 Onboarding/Academy 브라우저 스모크와 별도 PostgreSQL의 실제 학생·강사 가져오기·첫 로그인 흐름을 모두 통과했다. 명단 복사 화면의 로그인 문자열과 CSV의 수식 방지 처리가 섞이지 않는 회귀 검사도 포함한다.
